# Yohaku（余白）

**今日できる量を知り、次のひとつを決める。** 休息を先に確保し、時間と元気に合わせてプランを調整する、日本語のライフスタイル管理アプリです。サーバー・アカウント・有料API・外部AIは不要です。

公開先（Pages有効化後）：https://megaminxkr.github.io/yohaku/

## 機能

- **今日**：選択日の残りの活動時間について、タスク配置前の空き時間と配置後の余白を別表示。次のタスク、固定予定とタスクの時間割、完了状態を確認。
- **予定**：単発／毎週、当日だけの例外／繰り返し全体の編集・削除、休息・食事の時間確保、重複の警告、深夜をまたぐ予定。
- **タスク**：タイトルと残り分数で登録。カテゴリ、任意の締切、重要度、集中力、分割可否、状態を設定。手動時刻指定、部分完了、完了・再開。
- **生活チェック**：睡眠時間（任意）、元気度5段階、メモ（任意）。同日の修正可。健康状態の判断はしません。
- **提案**：説明可能なルールによる通常／短縮プラン。プレビューの適用まで既存プランは変更されません。短縮前の通常プランを保持し、復元もプレビューできます。
- **振り返り**：月曜はじまりの週単位で計画／実績、完了数、カテゴリ実績、生活記録を表示。未入力と0分を区別。
- **設定**：活動時間、予備時間（初期20%）、カテゴリ変更、JSON書き出し／検証・確認付き復元、二段階確認の全削除。
- 初回サンプルは任意選択。キーボードとタッチに対応し、スマートフォン／タブレット／PCでレイアウトを変更します。

## ローカル実行

Node.js **22.18以上**（CIは24）、npmを使用します。

```sh
npm ci
npm run dev
```

表示されたURLの `/yohaku/` を開きます。ページ内の画面切り替えにサーバールーティングは使用しません。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

ブラウザの自動テスト：

```sh
npx playwright install --with-deps chromium
npm run build
npm run test:e2e
```

ビルドしたアプリを `/yohaku/` で起動し、390 / 834 / 1440pxの3幅で操作をテストします。既存のプレビューに接続する場合は `YOHAKU_TEST_URL` に `/yohaku/` を含むURLを指定できます。OSにインストール済みのChromiumを使う場合だけ `CHROMIUM_PATH` を指定します。

```sh
TZ=Asia/Tokyo npm test
TZ=America/Los_Angeles npm test
```

## GitHub Pagesへの公開

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
2. `main` へのpushで **Check** が型チェック、単体テスト、3画面幅のブラウザ操作テストを実行します。
3. Checkの成功を受け、**Deploy Pages** がそのコミットをビルド・公開します。初回設定前に失敗した場合は、設定後に Actions → Deploy Pages → Run workflow を実行してください。
4. 完了後、https://megaminxkr.github.io/yohaku/ を開きます。

`vite.config.ts` の `base: '/yohaku/'` で、リポジトリ名を含むパスに対応します。リポジトリ名を変更するときはこの値も変更してください。独自ドメインは設定していません。

## 保存・バックアップ

- IndexedDBの `yohaku` データベースに保存。**現在の端末・ブラウザ・サイトのオリジンごとのデータ**です。別端末や別ブラウザには自動同期されません。
- 個人の入力をGitHubや外部サービスへ送信する処理、解析・広告SDK、外部フォントはありません。公開ファイルの取得はGitHub Pagesへの通常のWebアクセスです。
- ブラウザの保存データ削除、プライベートブラウズ終了、ストレージ自動削除などで失う可能性があります。保存の保持要求はブラウザが判断するため、JSONバックアップも必要です。
- 設定の「バックアップを書き出す」でJSONを保存。別の端末でも設定のファイル選択から復元できます。**復元はマージではなく全置換**です。件数と形式を確認してから置き換えます。
- JSONのバージョン、日付の実在、数値範囲、重複ID、カテゴリ、計画の参照先等を検証します。上限10MB。未対応バージョンは拒否します。
- 保存成功はIndexedDBトランザクション完了後に表示します。失敗時は未保存状態を明示して変更操作を止め、未保存の入力の書き出し・再試行を提供します。入力の検証エラーでは編集を続けられます。
- 複数タブからの上書きはrevision比較で検出します。古いタブでの変更をバックアップ後、再読み込みして続行してください。自動マージはしません。
- 読み込み時に壊れたデータや未対応形式を検出した場合、空データで上書きせずエラーを表示します。
- 保存形式は `version: 1`。移行入口は `storage.ts` の `migrate` に集約。今後バージョン追加時に段階移行を実装する構造です。

## 計画のルールと注意点

1. 端末ローカルの日付・分単位で計算。日付文字列はUTC日時としてパースしません。開始より早い終了は翌日です。同一開始・終了は入力エラー（24時間予定としては扱いません）。
2. 固定予定・休息を区間の和集合にまとめて空き時間から除去。重複分は二重に引きません。隣接日の深夜またぎタスクも除去します。
3. 現在より前の時刻には新規配置しません。予備時間分を差し引いて作業量の上限を求めます。初期20%は変更可能な計画上の値です。
4. 優先点は締切（今日1000、明日800、3日以内550、7日以内300）、重要度×80。元気度1〜2では `(4−必要集中力)×100` を加算。同点はID順で、同じ入力と基準時刻から同じ結果になります。
5. 分割不可はひとつの空き時間に全量が収まる場合のみ。分割可は空き時間に応じて配置。締切日の24時以降へ自動配置しません。置けない分は理由付きでプレビューに残します。
6. 手動の時刻・開始済みの配置は保持し、衝突や活動時間外、目安超過を表示します。手動配置の変更は一度「配置解除」して再指定します。ユーザーが明示的に入れた衝突は勝手に移動しません。
7. 短縮は保存した通常プランの未完了作業時間の半分（通常プランがなければ通常提案の半分）。分割不可や手動保持により一致しない場合も、実際の時間を表示します。適用時刻が変わったプレビューは再確認します。復元元の自動時刻が過ぎていれば、現在時刻で通常プランを再提案します。
8. **見積もりを進めた分**だけ残り時間を減らし、**実際に使った時間**は別ログに記録します。部分完了後は残り時間が変わるため、同じタスクのほかの未完了配置を解除します。完了済みのブロックと実績は残ります。
9. 未完了は翌日に自動コピーせず、次回の再計画候補です。過去の未完了配置は実績ではありません。タスクを編集・削除すると未完了の配置を解除しますが、実績ログは記録時のタイトル・カテゴリで残ります。

### 初期版の制約

- 提案は貪欲法で、最適な並べ方を保証しません。締切の検査は90日先までの空き時間による上限評価です。他タスクとの競合をすべて解く長期スケジューラではありません。収まらないと判定できたものを警告し、それ以外も完了を保証しません。
- 週の「計画」は**現在保存されている計画**の合計です。全ての再計画履歴を累積する指標ではありません。実績は入力したログのみで、自動計測・生産性スコアはありません。
- 実績の削除はタスクの残り分数を自動で巻き戻しません。必要に応じてタスクを編集してください。完了の取り消しも状態と残り分数を編集します。
- 繰り返しは開始日以降の同じ曜日です。当日の例外は全体編集後も残ります。当日の移動は取り消し＋単発予定の追加で対応します。月単位・終了日付き繰り返しはありません。
- オフライン用Service Worker、通知、アカウント、クラウド同期はありません。端末内保存であり暗号化された保管庫ではありません。
- 時刻はローカルの壁時計の分数です。夏時間で一日が23/25時間になる地域では実際の経過時間との差があり、日本のような夏時間のない地域を主な想定とします。

## 構成

```text
src/model.ts        型と初期値
src/time.ts         ローカル日付・時刻
src/planner.ts      純粋な区間計算・配置・警告
src/storage.ts      形式検証・移行入口・IndexedDB
src/actions.ts      完了・プラン適用などの状態変更
src/components.tsx  共通UI
src/App.tsx         画面とユーザー操作
src/style.css       レスポンシブ表示
 tests/            計画・保存・日付の単体テスト
 e2e/              主要操作のPlaywrightテスト
```

採用時の公式ドキュメント：
[React](https://react.dev/versions)、[TypeScriptのReact対応](https://www.typescriptlang.org/docs/handbook/react.html)、[Vite](https://vite.dev/guide/)、[ViteのGitHub Pages公開](https://vite.dev/guide/static-deploy#github-pages)、[Playwright](https://playwright.dev/docs/intro)。本番依存はReactとReact DOMのみ。バージョンと依存解決はpackage-lock.jsonに固定しています。
